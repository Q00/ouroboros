# RFC - Evidential force for self-authored acceptance contracts

> Status: Superseded for `ooo run` by monotonic verification. Stages 0–4 remain
> research proposals for a future sandboxed evaluation path; they are not part
> of worker execution or run acceptance.
> Scope: future `ooo evaluate` discrimination research only.
> Prior art in-repo: PR #1916 (hidden-checklist convergence),
> `docs/rfc/verify-gate-windows-portability.md` (shell resolution + vacuity finding)

## Superseding decision: monotonic verification

`ooo run` persists worker execution and machine verification as independent
facts. A verify command adds evidence; it never removes transcript obligations,
recovers a failed worker result, or causes completed work to be retried when the
verifier is unavailable. The runtime uses a resolved real Bash or records
`UNAVAILABLE`; it does not emulate Bash. Arbitrary negative-control commands
require a real sandbox and therefore stay outside the run critical path.

The remaining sections preserve the rejected prototype and the research
rationale so a future sandboxed `ooo evaluate` experiment can reuse the useful
analysis without reintroducing it into execution.

## Problem

### What #1916 actually closed, and the seam it left open

PR #1916 (merged 2026-08-07, `9210219`) is the hidden-checklist convergence
loop. Reading its diff and the code it left behind, it established three
things:

1. **Information asymmetry.** The worker never sees the grader's answer key.
   `_build_success_contract_block()`
   (`src/ouroboros/orchestrator/atomic_prompt_builder.py:34`) deliberately
   omits `verify_command` and `output_assertion` from every worker prompt
   (`expected_artifacts` stay visible — they are the work contract, not the
   grading key), and `src/ouroboros/orchestrator/contract_redaction.py`
   scrubs raw, quoted, and escaped encodings of the hidden values,
   longest-first, from every remaining worker-visible field, including retry
   evidence. The Seed handoff to workers is an opaque, session-bound handle;
   raw Seed paths are never forwarded.
2. **Judgment ownership.** The orchestrator — not the worker — runs the
   contract (`_run_ac_verify_gate`,
   `src/ouroboros/orchestrator/parallel_executor.py:9693`), so a verdict
   cannot be self-reported away.
3. **A closed loop over verdicts.** Evaluable runs continue into formal
   evaluation; rejected verdicts feed bounded Ralph evolution, under a
   single durable run→eval→evolve chain with collision-resistant lineage.

All three hold today. What #1916 never established — and, reading its diff,
never attempted — is that the hidden answer key *discriminates anything*.
Every mechanism in that PR treats the contract's content as given and
protects its **secrecy** and its **execution ownership**. None of its 52
changed files asks whether the command can fail. A `verify_command` of
`exit 0` is perfectly hidden from the worker, perfectly redacted from retry
evidence, executed by the orchestrator with full authority — and passes
unconditionally. The convergence loop then converges on that pass.

So the owner's reading is precise in both halves: #1916 was necessary
(without it, any strengthening of the contract is pointless — the worker
would just read the stronger key and optimize to its letter), and it was not
sufficient. **#1916 closed information asymmetry; it did not establish
evidential force.** A hidden check that always passes is still hidden.

The gap was not hypothetical. Measured in this repo before today's work:

- `exit 0` was the single most common `verify_command` generated by
  seed-architect: **13 occurrences** in the surveyed corpus.
- Declaring *any* `verify_command` drops `commands_run` and `tests_passed`
  from the required transcript evidence
  (`src/ouroboros/orchestrator/evidence/verification.py:44-56`), on the
  premise that the orchestrator's own execution replaces those checks. A
  vacuous contract therefore left an AC checked **less** than an AC with no
  contract at all — the gate built to make self-reporting impossible was the
  cheapest way around it.

### Residual motivating deferred evaluation research

The retired static-analysis prototype attempted to remove the constant-verdict floor.
It cannot reach the rest:

- `pytest -q` is not vacuous, but it may pass **before** the work is done
  (the suite does not cover this AC), so its pass carries no information
  about this run.
- The worker may author the test to pass trivially, weaken an existing
  assertion, or plant a skip-all `conftest.py` — all inside the workspace
  the worker owns, invisible to command-text analysis.
- `test -f out.txt` is satisfied by `touch out.txt`.
- An AC's semantic content ("the refund flow works end to end") is not
  entailed by any command's exit code.

One prior proposal is on record as **rejected** and stays rejected:
substituting workspace diff/mtime signals for missing transcript evidence.
`touch` satisfies it, and it inverts the reason the harness exists. (Git
*attribution* as an adjudicator-computed audit record is a different thing
and is adopted below — the distinction is that attribution informs and
flags; it never substitutes for a verdict.)

## Retired prototype baseline (historical; not implemented in `ooo run`)

The prototype combined the following mechanisms before the monotonic decision replaced it:
   (`src/ouroboros/core/verify_command_plan.py:338`) parses the command and
   commits to an answer only when every reachable step is a shell builtin
   whose status and output are fixed by literal arguments. Constant-True
   (`exit 0`, `true`, `printf READY` under an assertion expecting `READY`)
   → `AcceptanceCriterionSpec.has_evidential_success_contract`
   (`src/ouroboros/core/seed.py:616`) is False: the gate does not stamp the
   AC and the contract no longer buys the evidence exemption. Constant-False
   (`exit 1`) is left alone — it can only ever refuse. Unparseable → `None`,
   never an accusation.
2. **Seed-authoring gate.** `unverifiable_criteria()`
   (`src/ouroboros/core/seed_verify_gate.py:49`) reports ACs with no
   command and ACs with a vacuous one at authoring time, staged
   `warn` → `block` behind `seed.verify_command_gate`.
3. **Verify-environment sanitization.** `sanitized_verify_environment()`
   (`src/ouroboros/orchestrator/verify_shell.py:258`), wired at the gate's
   `create_subprocess_exec` site (`parallel_executor.py:9783`). Strips
   `PYTHONPATH`/`PYTHONSTARTUP`/`PYTHONHOME`/`PYTEST_ADDOPTS`/
   `PYTEST_PLUGINS`/`NODE_OPTIONS` and the `LD_PRELOAD*`/
   `DYLD_INSERT_LIBRARIES*` prefix families. `PATH` is deliberately kept: a
   workspace `.venv/bin` is legitimate, and stripping it breaks every real
   contract. Measured motivation: `PYTEST_ADDOPTS="--collect-only"` turns
   any pytest contract into exit 0 with zero tests run, and neither
   `PYTHONPATH` nor `PYTEST_ADDOPTS` is covered by the project-`.env`
   denylist (`src/ouroboros/config/untrusted_env.py` blocks the
   `LD_`/`DYLD_`/`UV_`/`PIP_` prefixes and `*_CLI_PATH`, not these).
4. **Windows portability + quarantine shape.** A real POSIX shell is resolved
   rather than inheriting the platform default (`resolve_verify_shell()`,
   `src/ouroboros/orchestrator/verify_shell.py`), and when no judgment
   environment exists, the retryable
   `FailureClass.VERIFY_ENVIRONMENT_UNAVAILABLE`
   (`src/ouroboros/orchestrator/verify_quarantine.py:17`,
   `failure_taxonomy.py:71`) — deliberately **not** `BLOCKED`, which
   forecloses route escalation and demands a human handoff. Nothing was
   judged, so nothing is failed and nothing is stamped. Every withhold
   introduced by this RFC is modeled on that shape.

   Also shipped from the same module: when no shell resolves,
   `plan_shell_free_execution()` is consulted and an admitted plan is executed
   by `orchestrator/verify_command_runner.py` with POSIX semantics
   (short-circuiting, per-command assignment prefixes, 127 for a missing
   command, one timeout budget for the chain). The withhold above is reached
   only when the command genuinely needs an interpreter — a pipeline, a
   redirection, an expansion. Refusing remains the safe direction; nothing is
   approximated.

## Comparative research

### The organizing observation

Every known gaming strategy against the residual — suite-passes-before-work,
tautological new test, weakened existing test, skip-all conftest, shimmed
runner binary, `touch` against an existence check — shares one signature:
**it makes the contract's verdict independent of the work**. The static
proof catches independence when it is provable from the command text alone.
The dynamic complement is to *measure* independence: run the same contract
in states where the work is absent. A contract earns evidential force
exactly when its verdict is a non-constant function of the worker's
contribution. This is the negative-control discipline from experimental
science, and its software form is the mutation-testing kernel: *a test that
cannot fail verifies nothing; a test must fail without the change*.

### gajae-code (GJC)

GJC's experiment harness solves adjacent parts of the same trust problem.
Verified present in GJC and absent here (grep of
`src/ouroboros/orchestrator/evidence/` finds no git-derived signal; grep of
`core/seed.py` finds no numeric metric field):

- **Adjudicator-computed change attribution.**
  `autoresearch/tools/run-experiment.ts:83` captures pre-run dirty paths;
  `log-experiment.ts:102` computes the iteration's modified files **from
  git**, never from an agent claim; `log-experiment.ts:395`
  (`computeScopeDeviations()`) permanently records files outside declared
  `scope_paths`/`off_limits`, keepable only with a justification. In
  ouroboros, `files_touched` is a worker claim checked against the
  transcript (`evidence/claims.py`) — there is no adjudicator-side ground
  truth at all.
- **Harness pinning.** `init-experiment.ts:79` requires the harness file to
  exist, exit 0, and emit a metric before it is accepted, then commits it
  and records a `baselineCommit`; `run-experiment.ts:29` gives the run tool
  **no command parameter at all**. ouroboros pins the command *string*
  (hidden since #1916) but nothing pins the *files that string executes*.
- **Tool-parsed numeric metrics with recorded disagreement.**
  `run-experiment.ts:158` parses `METRIC name=value` from stdout;
  `log-experiment.ts:186` records an agent-claimed value that disagrees
  without overwriting either side. ouroboros has only the literal-substring
  `output_assertion` — a boolean channel, no numeric one.
- **Retroactive flagging.** `log-experiment.ts:47`, `state.ts:149`: a
  result can be excluded from aggregation later without deletion. The
  natural ouroboros consumer is reflect's settled-AC skip
  (`evolution/loop.py:1790`, `externally_satisfied_acs`): passed ∧
  unchallenged → re-execution skipped is exactly where a stale or
  late-suspected pass hides.
- **Already equivalent — do not port:** write-once receipts (the event
  store is INSERT-only), session lease (`evolution/generation_claims.py`),
  loop-exhaustion-is-not-success (`evolution/loop.py:146`).
- **GJC has nothing on vacuity.** `receipts.ts:219` (`validateValidation()`)
  checks only `pass`, and GJC's own tests use `command: "true"`. GJC is
  safe there only because its validation commands are operator-supplied.
  ouroboros generates them with seed-architect — which is why the vacuity
  layer had to be invented here and why the dynamic layer below is needed
  at all.

## Decision

Four stages, ordered by (evidential force gained) ÷ (cost + risk of a false
PASS). Every stage obeys one invariant, inherited from the verify gate's
founding rule: **a probe's only authority is to withhold a stamp.** No probe
manufactures a PASS, no probe converts a worker pass into a run-stopping
failure, and an unadjudicable AC continues the run unverified — the
`VERIFY_ENVIRONMENT_UNAVAILABLE` shape, generalized.

### Stage 0 — Snapshot machinery (prerequisite, shared by Stages 1 and 2)

At run start, after workspace materialization and before the first worker
dispatch, capture an immutable snapshot of the workspace — tracked *and*
untracked content (`git stash create` does not cover untracked files
cleanly; write a temporary index via a scratch `GIT_INDEX_FILE` +
`git add -A` + `git write-tree`, or copy into the session scratchpad).
Snapshots live in the session scratchpad only. **Never materialize sibling
git worktrees** — a prior incident destroyed four of them.

The snapshot is the substrate for both probes below, which is the main
reason Stage 1 runs inside it rather than against the live tree: the
measured contract corpus contains `rm target.txt` (**2 occurrences**). The
existing workspace-mutation digest
(`_workspace_content_digest`, `parallel_executor.py:4996`) *detects*
mutation after the fact; running a baseline probe against the live pristine
workspace would let a destructive contract destroy it before any worker
starts. Probing a copy makes the hazard structurally impossible and
decouples the probe from dispatch ordering (parallel ACs share `_task_cwd`,
so a live-tree baseline would have to race the first dispatch; an immutable
snapshot can be probed at any time).

**Two containment rules the implementation settled (PR 1).** A copy is only
disposable if nothing inside it points out of it, and a baseline is only
authority if the next process can see it:

- Every symlink the copy inherits is contained or the snapshot is refused.
  Links that stay inside the copy are kept; a link to a regular file outside
  it (the `.venv/bin/python -> installed interpreter` shape every Python
  workspace has) is replaced by a copy of that file, which is what the link
  gave the command to read minus the write-through; anything else outside —
  a directory, a dangling target, a link back into the live tree — has no
  containment that preserves its meaning, so the baseline stays unknown.
- No checkpoint store, no baseline. The probe's records are written in a
  zero-levels checkpoint before the first dispatch; if that write cannot
  land, workers do not run under a baseline no resume can see. Nothing has
  been dispatched at that point, so the workspace is untouched and the run
  can simply be started again.

### Stage 1 — Baseline negative control (dynamic vacuity proof)

**Mechanism.** For every contract-carrying AC, run the full contract —
`verify_command` + `output_assertion` + `expected_artifacts` existence —
against a copy of the Stage 0 snapshot, reusing `_run_ac_verify_gate`
(timeout, output tail, sanitized environment all inherited). Record
`baseline_verdict: bool` per AC in the checkpoint next to
`verify_gate_outcome`, and which `expected_artifacts` already exist.

Consumption in `_apply_verify_gate` (`parallel_executor.py:9845`):

- Post-execution contract PASS with `baseline_verdict is True` → the
  contract discriminated nothing this run. Treat exactly like the static
  vacuity case: `has_evidential_success_contract` is off for this run, the
  transcript-evidence obligations are retained, emit
  `execution.verify.non_discriminating`, do not stamp. Never fail the AC on
  this signal.
- A baseline-passing contract also loses **recovery authority**: today a
  contract PASS flips a worker-reported failure to success
  (`execution.verify.recovered`, `parallel_executor.py:9905`). A contract
  that passed on the empty workspace must never resurrect a failed AC.
- An artifact that existed at baseline stops counting as evidence — it
  neither fails the AC nor supports it.
- A seed whose contracts *all* pass at baseline is a broken seed: surface
  immediately at run start through the same rendering channel as
  `render_verify_command_gate_warning`, and feed the finding back to the
  seed-QA loop.

**What it proves.** The verdict changed FAIL→PASS as a function of workspace
state produced by this run. It kills outright: the headline
`pytest -q`-on-a-green-repo case, pre-existing `test -f` targets, and every
*pre-planted* unconditional-pass strategy (a fake runner binary, skip-all
conftest, or tautology committed before run start all pass at baseline →
flagged). **What it does not prove:** semantic adequacy (`touch out.txt`
after a baseline where it was absent discriminates and still means
nothing), and it misses tampering performed *during* execution — both are
Stage 2's and Stage 3's territory.

**How it is gamed.** The worker cannot touch the baseline — it is captured
before the worker exists; temporal ordering is the whole defense. The
residual attacker is the seed author: a command engineered to fail at
baseline incidentally and pass trivially later
(`test -f .marker && exit 0`). The static planner already reaches part of
this (a chain whose final leg is constant-True is worth flagging —
open item below); the rest is Stage 3's entailment audit. Flaky tests that
fail at baseline and pass later by luck read as discrimination — accepted:
the guard's failure mode is only ever a missed withhold, never a false FAIL.

**Cost.** One command execution per contract AC per run, bounded by
`verify_command_timeout_seconds`; zero LLM calls; zero worker re-runs.
Seconds-to-minutes against 20-minute worker ACs. Position: run start
(probe), post-execution gate (consumption).

**Falsification.** (a) Seed an AC covered by the existing suite
(`verify_command: uv run pytest -q tests/unit/config` on green main):
baseline must PASS, post-gate must withhold and retain transcript evidence,
and `execution.verify.recovered` must be unreachable. (b) Seed a new-test
contract (`pytest tests/test_new_thing.py`): baseline FAIL (file absent),
post-pass stamps normally. (c) Noise floor: replay historical seeds'
contracts at their run-start commits and measure the fraction of
legitimately discriminating contracts that happened to pass at baseline. If
that fraction is high (>~20%), the withhold stays an evidence downgrade
forever and must not migrate toward blocking.

### Stage 2 — Oracle-discrimination probe (two-tree differential)

**Mechanism.** The mutation-testing kernel run once, in the cheap
direction: *the test must fail without the change*. Post-execution, only
for a contract that passed **and** was baseline-discriminating (Stage 1
filters first — it is cheaper), build **tree A = Stage 0 snapshot + the
worker's oracle files**, where the oracle set is deterministically
approximated: (i) every workspace path appearing as a token in the
`verify_command` argv (reuse `plan_shell_free_execution`'s tokenizer;
shlex fallback when it returns `None`); (ii) worker-modified files under
conventional test roots (`tests/`, `test_*.py`, any `conftest.py`);
(iii) `pytest.ini`/`pyproject.toml`/`setup.cfg` when worker-modified.
"Worker-modified" comes from Stage 4's git attribution, not from claims.
Run the identical contract in tree A under the sanitized environment.
Required outcome: **FAIL on A** (PASS on tree B, the real workspace, is
already established). A-PASS → the pass survives removal of the
implementation → `non_discriminating`, withhold, run continues.

**What it proves.** The pass is *caused by* the worker's non-oracle work —
the strongest statement an exit code can make. It closes the
during-execution hole Stage 1 leaves: a worker who weakens a test to a
tautology, plants a skip-all conftest, or shims the runner does so inside
the oracle set, so tree A carries the sabotage without the implementation
and passes → flagged. Implementation hidden inside test files puts the
implementation into tree A → A passes → flagged. Both cheats fail toward
withhold, never toward PASS.

**What it does not prove.** Semantic adequacy (a discriminating-but-trivial
proxy passes both probes). Oracle-set completeness: a helper module outside
test roots that the test imports lands on the implementation side, so tree
A fails "correctly" for an incidental reason — false *confidence*, not a
false PASS, since the verdict direction is unchanged. Two known noise
sources, both safe-direction: single-file deliverables where
oracle ≡ implementation (A ≡ B → A passes → withhold; report as "contract
cannot be discrimination-probed", keep transcript evidence) and sibling-AC
coupling (tree A lacks sibling work, the test fails on A with an import
error rather than an assertion — stamp proceeds; log the A-failure reason
string for audit).

**How it is gamed.** To beat Stages 1+2 together, the command must pass
only in the presence of the worker's non-oracle files — i.e. the test must
actually detect the implementation. The remaining cheat is a semantically
empty implementation detected by a semantically empty but discriminating
test (`touch` + a new existence assert). That residue is irreducible at
this layer; it is exactly the Stage 3 / evaluation-stage boundary.

**Cost.** One tree materialization + one command run per *passing* contract
AC, post-execution only. No LLM, no worker re-run. Roughly doubles verify
wall-clock — trivial against the worker's. Gate behind config like
`run_verify_commands`, staged observe → enforce like the seed gate.

**Falsification.** Fixture workers, one per attack: (a) tautological new
test, (b) global-skip `conftest.py`, (c) fake `pytest` console-script shim
inside the workspace venv, (d) an existing assert weakened to
`assert True`. All four must yield A-PASS → withheld. The honest fixture
(real test + real implementation) must yield A-FAIL/B-PASS → stamped. Then
run the probe over a corpus of presumed-honest historical passes and
measure the withhold rate; >~10% noise means the oracle classifier needs
the declaration variant: the worker *declares* its oracle files and the
declaration is re-checked deterministically (the declared set must make the
command runnable on tree A) — a claim we verify, never a verdict we accept.

### Stage 3 — Authoring-time entailment audit (LLM classifies, gate re-checks)

**Mechanism.** The semantic gap is not mechanically closable, but it is
mechanically *narrowable at authoring time*, where an LLM call is already
budgeted (the seed-QA loop). Extend `seed_verify_gate` beyond vacuity: a
classifier receives (AC description, `verify_command`, `output_assertion`)
and returns a structured claim —
`{checks: "<the concrete predicate the command tests>",
strength: entails | partial | existence_proxy | unrelated}` — anchored by
two deterministic re-checks: (i) when `plan_shell_free_execution` shows the
command is pure `test -f`/`test -d`, `strength` is capped at
`existence_proxy` regardless of the classifier's opinion; (ii)
`existence_proxy`/`unrelated` findings render into the existing warn
channel and feed seed-QA iteration, demanding a stronger command or a
`verify_exemption_reason`. The classifier never touches a run verdict — it
shapes the contract before any worker exists, when the contract is cheap to
fix and its author has no gaming incentive (the worker never sees this
stage and cannot influence it).

**Proves / does not.** The only available pressure on
discriminating-but-trivial contracts — applied by preventing their
authorship, not by catching them later. It guarantees nothing; a determined
proxy survives; the classifier will mislabel.

**Cost.** One LLM call per AC at seed time, inside an already-iterating QA
loop. Position: seed authoring only.

**Falsification.** Hand-label ~50 (AC, command) pairs from historical
seeds; measure the false-accusation rate (a genuinely entailing command
labeled proxy/unrelated). Above ~5%, pin at `warn` permanently. The
spec-verifier history (#1926 → #2065) is the governing precedent: a
classifier's authority must be structural, because narrowing its prompt
gets pierced every round — hence advisory-only from day one, with no FAIL
authority ever granted that would later need revoking.

### Stage 4 — GJC borrowings (audit substrate)

Independent of the probes, adopt three GJC mechanisms as audit substrate.
None of them decides a verdict; all of them make later suspicion cheap and
grounded.

1. **Adjudicator-computed change attribution.** Record the worker's actual
   modified paths from git (pre-dispatch dirty-state capture + post-AC
   diff), per AC, into the event store. Consumers: Stage 2's oracle-set
   construction ("worker-modified" above), scope-deviation reporting
   analogous to `computeScopeDeviations()`, and the evaluation stage. This
   is not the rejected diff/mtime substitute: attribution never stands in
   for a verdict — it attributes, flags, and feeds probes.
2. **Numeric metric channel.** An optional
   `metric_assertion: {name, op, value}` on `AcceptanceCriterionSpec`,
   parsed by the orchestrator from verify-command stdout
   (`METRIC name=value` line format, as `run-experiment.ts:158`). Where a
   worker-claimed value disagrees with the tool-parsed one, record both
   without overwriting either (`log-experiment.ts:186`). Strictly stronger
   than the boolean `output_assertion` for quantitative ACs; same
   execution path, no new authority.
3. **Retroactive flagging.** A terminal-state-preserving
   `execution.verify.flagged` event that excludes an AC's pass from
   aggregation (and from reflect's settled-AC skip at
   `evolution/loop.py:1790`) without deleting or rewriting history. This is
   the landing zone for anything Stages 1-3 learn *after* a pass was
   stamped — including a Stage 2 probe run retroactively over old runs.

Harness *pinning* in the full GJC sense (commit the oracle before the run,
give the run tool no command parameter) is subsumed for our dominant case
by Stages 0-2 — the snapshot pins the pre-state and the discrimination
probe checks the oracle's relationship to it — and noted as an open item
for the case it still covers (operator-supplied fixed harnesses).

## The ceiling — what a stamp can and cannot mean

With Stages 0-2 and the sanitized environment, a stamped PASS certifies:

> a contract fixed before execution and hidden from the worker (#1916),
> which failed on the pristine workspace (Stage 1), passes on the worker's
> workspace, was computed by the orchestrator in a sanitized environment,
> and whose pass does not survive removal of the worker's non-oracle
> contribution (Stage 2).

That is a **discrimination certificate**. It is also the ceiling for
exit-code mechanisms: no command's status can entail "the refund flow works
end to end", because the semantic adequacy of an oracle is precisely the
problem the oracle was introduced to solve — the regress terminates at a
human- or holdout-authored oracle, or it does not terminate. Pretending
otherwise is how a verification layer becomes a reward-hacking surface.

The honest architecture therefore names the tiers instead of conflating
them:

- **Two-valued verdict vocabulary.** `discriminating_pass` (contract passed
  and both probes held) vs plain `pass` (contract passed; probes withheld
  or inapplicable) in the durable evidence record, with the evaluation
  stage weighting them differently. One new field on the serialized
  `_VerifyGateOutcome` (`orchestrator/verify_gate_outcome.py`), following
  the existing bounded-schema discipline there.
- **One shared withhold.** `non_discriminating`, modeled explicitly on
  `VERIFY_ENVIRONMENT_UNAVAILABLE` (`verify_quarantine.py:17`): the AC
  completes, is not counted verified, the run continues, and the finding
  surfaces to the operator and the seed-QA loop. Retryable, never
  `BLOCKED`, never a manufactured FAIL.
- **The un-probe-able residue** — single-file deliverables, exempted ACs,
  non-code ACs without a command — falls back to what already exists:
  transcript-backed evidence plus staged semantic evaluation. Weak, and
  labeled as weak. The label is the deliverable.

## Deferred evaluation rollout

1. **Future sandboxed evaluation: Stage 0 + Stage 1 + vocabulary.**
   baseline probe, `baseline_verdict` in the checkpoint,
   `non_discriminating` outcome + event, recovery-authority revocation,
   `discriminating_pass`/`pass` field. Observe-only: withholds are emitted
   and logged, evidence exemption unchanged, for one release. Then flip the
   exemption consequence on by default (mirroring how
   `run_verify_commands` and the seed gate staged in).
2. **PR 2: Stage 4.1 (git attribution).** Needed by PR 3; independently
   useful for scope reporting.
3. **PR 3: Stage 2.** Behind config, observe → enforce, with the fixture
   attack suite from its falsification plan landing in the same PR as the
   regression harness.
4. **PR 4: Stage 3** riding the existing seed-QA loop at `warn`.
5. **PR 5: Stage 4.2-4.3** (metric channel, retroactive flagging) as
   demand appears.

Each stage's falsification experiment is run *before* its enforce flip, and
its measured noise rate is recorded in the PR body.

## Explicitly out of scope

- **Diff/mtime as substitute evidence.** Rejected previously; stays
  rejected. Attribution (Stage 4.1) informs and flags, never adjudicates.
- **Cross-model second-opinion contracts** (a second LLM re-derives a
  verify command from the AC description alone, downgrade-only authority).
  Skirts the "an LLM must not generate the decider" line; its false-flag
  rate will be dominated by wrong-path guesses. Not before Stages 1-2
  telemetry exists to compare against.
- **Metamorphic relations** (idempotence, permutation invariance) for
  output-producing contracts. Applicable to a small AC minority; revisit if
  non-code seeds grow.
- **Full mutation testing** (mutate the implementation, count caught
  mutants). Minutes per AC; the single-direction Stage 2 probe captures
  most of the value at a fraction of the cost.
- **Worker re-runs of any kind.** Nothing here re-executes a ~20-minute
  worker.
- **Holdout evaluation sets** (OctopusGarden #91). Complementary,
  separately tracked.

## Open items for implementation

1. **Snapshot representation.** Scratch-index `git write-tree` vs plain
   copy into the session scratchpad. Copy is simpler and covers non-git
   workspaces; write-tree is cheaper for large repos. Decide in PR 1; both
   must respect the sibling-worktree ban.
2. **Constant-tail chains.** Extend `constant_verdict()` to flag commands
   whose *final reachable leg* is constant-True behind a real predicate
   (`test -f .marker && exit 0`) — statically reachable today, currently
   returns `None`. Closes part of Stage 1's seed-author residual.
3. **Baseline verdicts for destructive contracts.** `rm`-bearing contracts
   mutate even the snapshot copy; the copy is disposable, but the probe
   must use a *fresh* copy per AC, not a shared one. Cost of N copies vs
   one copy + restore — measure in PR 1.
4. **Oracle-set classifier precision.** Conventional-path heuristics
   (Stage 2 i-iii) vs worker declaration with deterministic re-check.
   Start heuristic; the falsification corpus decides whether declaration is
   needed.
5. **Reflect interaction.** A `non_discriminating` AC must not enter
   reflect's settled set (passed ∧ unchallenged → skip), and a
   retroactive flag (Stage 4.3) must evict it. Wire both when the flag
   event exists.
6. **Cached-outcome revalidation.** `_revalidate_cached_verify_gate_outcome`
   (`verify_gate_outcome.py:186`) refreshes the artifact leg at
   finalization; the `baseline_verdict` bit must survive checkpoint
   round-trips under the same bounded-schema rules.
7. **Operator-pinned harnesses.** The GJC `init-experiment` pattern (commit
   the oracle, no command parameter at run time) for the case where a human
   supplies the contract; interacts with `verify_exemption_reason` design.
